# Shorts 制作・運用ガイド

出典：「Shorts 制作・運用ガイド（CREATOR PLAYBOOK / 2026.11）」7本の要点を、企画から検証までの共通手順へ統合したもの。

> 視聴者の問いから始める。初稿から仕上げ、実測から次の一本を磨く。

## 使い方

- 最初に共通の制作順序（下の 2〜7）を確認し、**今回の依頼に必要な工程だけ使う**。
- 7本の原資料を毎回再調査したり、紹介された機能をすべて設定したりする必要はない。
- 投稿や仕様に関わる条件は、**実行時の公式情報と画面で確認**する（本ガイドの機能情報は 2026-11-12 時点）。
- 本ガイドは既存資料の統合であり、チャンネルの実データ確認や実操作の報告ではない。公式条件／推奨／効果の仮説／操作済み を区別して扱う。

## 1. 共通ルールとプロジェクト固有ルール

### 共通の軸
視聴者の問い / 事実と素材許諾 / 独自の場面 / 音声との同期 / 内容に合う包装 / 条件をそろえた検証。

新しいチャンネルでは、語り口・尺・色・キャラクター・固定台詞・素材条件を先に確認し、他の演出を無条件に移植しない。

### Shorts タイトル共通指定
- Shorts タイトルの末尾は **半角スペース付きの「 #shorts」** にする。
- その後ろに文字や別タグを置かない。
- 長尺や台詞には自動付与しない。
- これは編集指定であり、再生増を保証する仕組みではない。

### 真面目の芽（固有ルール）
- 女性の常体、人物固有の葛藤・選択・変化、比喩と呼びかけを維持。
- 色・意匠：白・赤・黄と芽アイコン等の指定を維持。
- 本人と分かるフリー素材を、本編・サムネイル・収益化・必要な加工に使えることを**推薦前に確認**。不成立の明示指定人物は制作前に例外確認する。
- 締めは必ず **「小さな芽を、育てていこうか。」**。後続の台詞や CTA を足さない。
- この本人素材条件と例外確認は他の企画へ自動適用しない。

### 君 ai 夢想（固有ルール）
- 固有の固定台詞と OP・ED、依頼された尺を維持。
- 実在する AI 活用を扱い、**実用・研究・構想を区別**する。
- 技術の限界と日常への帰還を残す。
- 真面目の芽の締めへ置き換えない。

## 2. 視聴者の問いから需要・参考を調べる

- 企画は「**誰が、どの状況で、何を知りたいか**」を一文にする。年齢・性別だけで細分化しない。
- 見終わったときに分かることを**一つ**定める。
- 需要が強くても、**事実で答えられず、使用可能な素材がなければ採用しない**。
- 小規模チャンネルへの一律の優遇は前提にしない（関心・競合・季節性も表示機会に影響）。
- Studio のトレンドや Shorts のコンテンツギャップは「満たされていない問い」の手がかり。語句・対象期間・観察日・実際の表示内容を記録。ボタンが出ない場合に実測済みと書かない。ギャップは競合ゼロの保証ではない。
- 参考動画は同形式・近い尺・近い公開期間を優先し、好成績だけでなく通常実績も比較。URL・公開日・観察日・総再生数と取得時点を残す。
  - 「今週／今月」は公開日フィルタであって再生増分ではない。伸びを測るなら複数時点の差分。
  - シークレット検索は比較の補助に留める。
- 文字起こしで分かるのは言葉と開示順だけ。表情・カット・字幕位置・間・BGM は観察したことにならない。「確認した内容」と「反応に影響した可能性」を分ける。
- 持ち帰るのは**需要と構造の仕組み**。独特の台詞・比喩・素材・場面配列は持ち帰らない。
- 参考の逸話は別に裏付ける。**AI に本人の架空の内面・会話・実績を補わせない**。名前だけ替えた反復ではなく、各回に固有の事実と変化を加える。

## 3. フック・台本・秒数・場面を一続きに設計する

- 最初に問いと仮フックを決め、**本編を完成させてから冒頭を最終編集**する。
- 第一画面で対象や違和感が分かり、最初の数秒で「何を見届けるか」が伝わるか点検。「0.5秒」「3秒」は目安であり成功条件ではない。
- フック候補（違和感／意外な矛盾／視覚的変化／結果先出し 等）を内部比較する。
  - 結果先出しでも結末を全部説明せず、過程の「なぜ」「何を選んだ」を残す。
  - 既知の主語まで隠して分かりにくくしない。
  - 煽り、無関係な衝撃映像、読めない点滅を強さの代わりにしない。
- 台本は経歴や一般論を並べず、問いに関係する**具体的な出来事**を選ぶ。各場面で新しく分かることを明確にし、**事実 → 選択 → 変化 → 回収** へ進む。
- 同じ答えを後半のクイズで再度聞かない。固定の締めがある企画では、その前に回収を済ませる。
- 尺は依頼と内容で決める。90〜180秒は指定時のみの範囲で、既定尺にしない。運用案：
  - 90秒：一つの選択や実演に絞る回
  - 120秒：転換と理由まで示す回
  - 150〜179秒：第二の比較や検証に新しい価値がある回
  - ※公式の最適尺ではない。180秒への引き延ばしや極端な早口は勧めない。
- 一度の制作依頼には、**内部比較と編集者点検を済ませた最善の完成稿を一本**出す。初見の分かりやすさ・根拠・回収・読み上げの自然さを提出前に直す。ユーザーの指摘を通常の修正工程に組み込まない（ただし完璧さや再生結果は保証しない）。

## 4. 画像・字幕・声・BGM／SE を編集する

- **音声先行**：声を試聴し、語り口と基本速度を先に確定。原稿と読み上げを一致させ、実音声の長さに字幕・画像・音を合わせる。速度や文面を変えたら同期と総尺を再点検。速さで詰め込まず、重複を削り必要な間を残す。
- 画像には「対象／操作／比較／結果」のいずれかの役割を持たせる。カットは一定秒数ではなく、**指す対象や意味が変わるところ**で切る。
  - 一般写真に囲み線を足しただけなら「認識のイメージ」等と示し、実機の判定結果と偽らない。
  - 生成画像や再現図を記録写真・実話の証拠にしない。
- 字幕は声に同期。問いは短く一つ。答えが出たら問いを撤去し次へ。声の字幕・強調字幕・固定テロップで同じ文を三重にしない。小画面で読める量と位置を確認。まとめカードは役立つ場合だけ、普通に読める時間で。
- BGM は語りと題材に合わせ、音量を固定％で決めない。転換前に下げる、説明は薄く、重要な一言は短い無音で受ける等。
- SE は撮影・判別・対象の切り替え等の**出来事**に置き、全語に足さない。研究段階の話に成功チャイムを重ねるような誤解を避ける。
- 音源は利用方法と曲ごとの条件を確認。**YouTube Audio Library を優先候補**、帰属が必要なら説明欄に記載。アプリ内音楽と編集ソフトに取り込む音源を同じ許諾と扱わず、二重再生も確認。
  - 2026-11-12 時点：1分超の Shorts に有効な Content ID 申し立てがあると全世界ブロック対象。「無料・商用可」「小音量」だけで安全と判断しない。

## 5. タイトル・縦サムネイル・説明・公開前設定を整える

- タイトルとサムネイルは**一組**で作る。タイトル前半に具体物・矛盾・問い、サムネは主役と短いコピーで補完。文字数や暗い帯を固定仕様にせず、スマホ一覧で内容と可読性を確認。
- 説明冒頭は動画固有の内容と主な語を自然に書き、その後に出典・クレジット・補足。
- Shorts の第一画面と一覧画像は**別の入口**。縦サムネを作っても設定済みではない。カスタム画像の利用資格・アカウント確認・設定方法・反映状況は実行時に再確認。使えなければフレーム選択方法を確認し、設定のためだけに締めの後へ静止画を足さない。
- タイトル末尾「 #shorts」を点検。他のハッシュタグは直接関連する少数に。詳細設定のタグ欄は表記ゆれ等の補助に絞り、キーワード羅列で埋めない。
- 確認項目：原語、タイトル・説明の言語、カテゴリ、対象視聴者、公開範囲、日時とタイムゾーン、通知の選択状態。デフォルト設定が当該アップロードに反映されたかも見る。
- 子ども向け設定は再生や収益目的で「いいえ」に固定せず、制作意図と内容で判断（大人も見る、だけでは除外できない）。
- 投稿時刻は視聴者データを起点に比較。19時固定や端末による罰を前提にしない。

## 6. 任意機能と Shorts・長尺の違いを判断する

- **関連動画**：見終えた人が次に知りたい内容があり、機能を使える場合に検討。クリック可能な導線であり自動移動ではない。各 Shorts の問いは一本で回収し、固定の締めの後に案内台詞を足さない。
- **共同投稿**：実際の協力・同意・素材許諾・投稿先と収益の扱いが合意できる場合のみ。相手の全登録者への到達や収益の自動分割を前提にしない。
- **多言語化**：原版完成後に検討。字幕トラック・投稿文・焼き込み文字・別言語音声を別々に校正。自動吹替と録音済み多言語音声は別機能。固定台詞の変更は無断で行わない。
- 2026-11-12 時点：公式のタイトル・サムネイル A/B テスト、プレミア公開、Hype は **Shorts 対象外**。
- 公式は Shorts の実績が長尺の推薦に悪影響を与えないと説明。ただし長尺は尺に合わせて導入と展開を設計し、Shorts の冒頭3秒やフィード指標をそのまま流用しない。
- 商品タグ・アンケート・再生リスト・チャンネルキーワードは目的に合う場合の補助で、全部必須にしない。
- 収益化は参加資格と審査を別途確認。数字の達成だけで合格や収入を約束しない。
- 設定・招待・投稿・外部サービス登録は、**依頼・許可の範囲で実行した操作だけを完了と報告**する。

## 7. 公開後に分析し、需要を保って検証する

- 分けて見る指標：フィードの表示機会／視聴を続けた割合とスワイプ／平均視聴時間・平均視聴率・維持率の谷。
  - 検索やホーム等の CTR は登録サムネイルインプレッションに対応する指標で、Shorts フィード全体の視聴選択率ではない。
  - 平均視聴率80％ ≠「80％の人が完了」。視聴回数とエンゲージビューも区別。
- 冒頭が弱い → 問いの見せ方を改善候補に。途中が弱い → 出来事までの長さや重複説明を改善候補に。
- 表示が少なくても需要不成立と即断せず、権利上の制限や外部要因も確認。「維持80％・スワイプ40％」「インプレッション100以下」等を普遍的な合否基準にしない。
- 24時間・72時間・7日など同じ観測点を設けるのは運用案。同形式・近い尺・題材・経過時間・流入面で比較し、小さなサンプルや前後差から因果を確定しない。
- AI の説明は改善仮説に留め、**未提供の Studio 数値は「未確認」**とする。手動の順次変更や別動画比較を公式 A/B テストと呼ばず、同一動画の重複投稿も標準化しない。
- 次の一本：視聴者の問いを保ちつつ新しい事実や場面を加え、**主な変更を一つ優先**。記録項目は「問い／今回の見どころ／確認指標／変更点／見る指標／未確認要因」。
- 長尺展開は登録者数から視聴人数を仮定せず、形式間の視聴者の重なりと実データで判断。
- 一本の低再生だけで題材を捨てない。ただし根拠や素材が成立しなければ見送る。
- 公開後検証を弱い初稿の言い訳にしない。

## 付録：原資料7本の採用ポイント

1. **添付テキストの要点と Shorts 制作ルール**：第一画面で主役や違和感を伝え、冒頭で見届ける問いを作る。画像・字幕・音を言葉の意味へ合わせる。結果先出しでも「なぜ」「どう変わった」を残す。入口・途中の離脱を分けて分析。
2. **投稿前チェックと冒頭3秒**：本編完成後に冒頭を磨き、説明欄・サムネ・投稿時刻・タグ・タイトル前半・投稿方法を点検。第一画面と一覧画像は別に確認。文字数や時刻の固定説は不採用。
3. **言語・需要調査・公開設定**：実際の言語と対象視聴者を正しく申告。コンテンツギャップを企画の手がかりに。設定の整備を内容の代わりや再生保証にしない。
4. **参考分析から独自企画を作る**：参考動画の需要・切り口・開示順を抽象化し、別に確認した事実とチャンネルの強みで新作に。根拠と素材が成立する案だけ採用し、タイトルとサムネを内部比較して一本に絞る。
5. **視聴者に届く制作と AI 補助**：誰が何を見届けたいかを先に決め、AI は負担の大きい工程へ。事実点検と音声先行の同期確認は残す。共同投稿・多言語化・収益化は目的と条件が合う場合のみ。
6. **Shorts 設定の適用と回遊設計**：機能は対象形式と目的で選ぶ。検索の条件・音源の権利・翻訳の層・関連動画の導線を区別。「設定変更で推薦が増える」万能説は不採用。
7. **視聴者の問いと改善の積み重ね**：低再生や登録者数だけで題材を判定せず、同じ需要を新しい出来事から掘る。表示機会・入口・途中の維持を分け、次の一本で主な変更を一つ優先。
